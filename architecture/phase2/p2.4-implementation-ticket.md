# P2.4 ticket — command/readback convergence

Status: **planned, not implemented**. Depends on P2.1 desired state and P2.3
quality; uses P2.2 transitions for audit.

1. Define/persist per-target pending deadline and command association, with
   convergence timeout independent of freshness. Require an explicit validated
   WRITE-binding/subtarget → READ-binding/readback-selector mapping; the
   current enum has no READ_WRITE direction. Without mapping use UNVERIFIED.
   Extend validated binding/definition metadata for this mapping; current
   binding configuration does not admit readback selectors or tolerance.
   Distinguish request, durable acceptance, publish, device ACK, and qualified
   readback. Use backend ACK receipt time for latency; never trust ACK device
   timestamp as the only clock.
2. Keep command lifecycle (ACCEPTED_FOR_DISPATCH, PUBLISHED, ACKNOWLEDGED,
   REJECTED, FAILED, TIMED_OUT) separate from verification
   (NOT_APPLICABLE, NO_DESIRED_STATE, PENDING, CONVERGED, DIVERGED,
   TIMED_OUT, UNVERIFIED). SUPERSEDED is historical intent disposition.
   Accepted ACK alone yields UNVERIFIED for write-only actuators. A readback
   must be valid, fresh, post-intent under the contract's observation criterion
   (sequence/echo or an explicit new observation cycle; unsolicited late
   arrival is insufficient),
   same target, and match configured
   equality/tolerance. Unattributed readback remains explicitly uncertain.
3. Support exact BOOLEAN/ENUM/STRING, capability-specific numeric tolerance
   in matching units, and OBJECT only with an explicit comparator. New intent
   supersedes old without deleting history; duplicate/late ACK cannot
   resurrect superseded intent. Late readback updates reported state only if
   accepted and evaluates the **current** desired target without inventing
   command causation. Do not auto-clear desired on convergence; rehydrate
   deadlines on restart.
4. Test matching/nonmatching/missing readback, no ACK, rejected/duplicate/late
   ACK, publish failure, write-only LED/RELAY, numeric tolerance, object
   without comparator, channel targeting, supersession, restart, and
   simulated MQTT E2E. UI must label unverified state honestly.

Acceptance: neither MQTT publish success nor device ACK is presented as
physical convergence; every terminal state has inspectable evidence.
