# NexusDeviceSdk: the NEXUS device helper library for ESP32

A small C++11 library that lets a device speak NEXUS wire contract 1.0 (profile `esp32-legacy-v1`) without re-deriving the rules: it builds telemetry and acknowledgements, evaluates received commands exactly as the committed firmware does, generates stable message ids, and ships a reference device and two samples.

**Status: tested on the host only.** The code is built with g++ (C++11, `-Wall -Wextra -Werror -pedantic`) and run against the repository's golden files. It has not been compiled with the ESP32 toolchain, not linked against the real `256dpi/MQTT` library, and never flashed. Nothing in this directory is a hardware-validation claim. `firmware/` is not modified and not imported.

## Layout (PlatformIO and Arduino)

```
library.json  library.properties  platformio.ini
src/NexusSdk.h            the one header to include
src/NexusArduino.h        Arduino glue (templated on the MQTT client; only for sketches)
src/nexus/*.h, *.cpp      Core (clock, freshness, ids, topics), Messages (telemetry, ack, command), DeviceNode (reference device)
examples/TemperatureNode, examples/LedCommandNode
test/host/                host unit tests and the sample driver
test/stubs/               Arduino, WiFi and MQTT stubs (host only, not the real APIs)
test/golden/commands.tsv  140 command cases with expected verdicts (generated by tools/gen_golden.py)
tools/gen_golden.py       regenerates / checks the golden file against the contract validator
```

## What the library does

| Need | API |
|---|---|
| Is the clock trustworthy? | `clockIsSynced(now)`; every timestamped builder returns `CLOCK_NOT_SYNCED` before it is |
| Telemetry | `buildTelemetry` with `Telemetry::ofNumber / ofInteger / ofBoolean`; contract 1.0 form (with `messageId`) or the legacy firmware form (`messageId` = NULL) |
| Stable ids | `MessageIds(bootId)`: one id per NEW sample from (boot id, counter); a retry reuses the id (`idFor`, or resend the same bytes) |
| Command received | `evaluateCommand(payload, length, now)` returns a `Disposition`; the firmware's order: clock, JSON, commandId, fields, capability/command, freshness |
| Acknowledge | `buildAck` (`ACCEPTED`, or `REJECTED` + `MALFORMED / UNSUPPORTED / STALE / DEVICE_REJECTED`) |
| Whole device | `DeviceNode` with three platform calls (`Hal`: clock, publish, LED) |

Freshness is the firmware's rule: a command is `STALE` when `|now - timestamp| > 30` s, with the whole-second device clock (decision D4). A command up to 30 s in the future is fresh.

## Where it differs from the committed firmware (deliberately, and tested)

| Library | Firmware | Why |
|---|---|---|
| commandId must be canonical UUID text, otherwise no acknowledgement | any string is accepted and acknowledged | the acknowledgement schema requires a UUID; the Python SDK does the same |
| a duplicate member name anywhere in the command is `NO_ACK:NOT_JSON` | ArduinoJson keeps the last one | the contract forbids duplicates (the validator rejects them) |
| payload over 512 bytes, nesting over 32, over 96 members: `NO_ACK:NOT_JSON` | no explicit bound | fixed memory, no heap; real commands are about 200 bytes |
| a boolean telemetry value needs a `capabilityKey` (`INVALID_FIELD` otherwise) | sends numbers only | the legacy shape of the contract is numeric; booleans belong to the generic shape |
| text fields are printable ASCII | n/a | no escaping of non-ASCII is implemented |

## Running the tests

```
python test/build_host.py                 # from sdk/esp32: build with g++, run unit tests and both samples against the stubs
python tools/gen_golden.py --check        # the golden command file is current and agrees with the contract validator
python -m unittest tests.test_esp32_library    # from sdk/python: the full conformance judged by the Python validator and SDK
```

`platformio.ini` defines a `native` environment for the same host tests and a `samples` environment for the ESP32 board. The `native` environment was executed once (PlatformIO Core 6.2.0, platform native 1.2.1, `pio run -e native`, then `program <repository root>`): it built and all 220,179 checks passed. The `samples` environment was **not** executed (no ESP32 platform or toolchain was installed); the automated tests use `test/build_host.py` with plain g++.

## What is and is not verified

Verified on the host: telemetry and acknowledgement bytes (equal to the committed firmware's fixtures in the legacy form, equal to the Python SDK in the contract 1.0 form, accepted by the contract validator), 140 command cases (equal to the contract validator under the ESP32 profile and to the firmware transcription), the 30-second absolute freshness boundary (the same verdicts as the Python SDK, the simulator and the backend's delivery window), stable and unique message ids, the explicit clock-not-synced refusal, buffer-overflow safety at every capacity, and the two samples against stubs.

Not verified: compilation with the ESP32 Arduino core, linking with the real MQTT library, NTP behaviour, GPIO, memory use on the device, timing, or any physical behaviour. An acknowledgement from this library means the device accepted the command; it is not evidence of a physical result.
